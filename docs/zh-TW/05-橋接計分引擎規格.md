# 05|橋接計分引擎規格

> 螢火 Firefly|v0.1|2026-07-20|AGPL-3.0
> 基底:X Community Notes 開源實作(https://github.com/twitter/communitynotes)之矩陣分解計分,裁剪至本專案規模

## 模型

每筆投票建模為:

```
r_{u,c} ≈ μ + i_u + i_c + f_u · f_c
```

- r_{u,c}:貢獻者 u 對卡片 c 的評分(有幫助=1/沒幫助=0)
- μ:全域截距
- i_u:貢獻者寬鬆度(有人什麼都投讚,先吸收)
- i_c:**卡片品質分(我們要的訊號)**
- f_u · f_c:貢獻者立場向量 × 卡片傾向向量(同溫層噪音,吸收後丟棄)

以正則化交替最小平方或 SGD 求解;維度初期 1 維(同 Community Notes),不足再升維。

## 顯示決策

- 卡片狀態機:`draft → candidate → displayed / not_displayed`
- candidate → displayed:i_c ≥ θ_helpful(初始 0.40,沿用 Community Notes 公開閾值,實測校準)且有效投票數 ≥ N_min(初始 5)
- displayed 卡片持續重算;跌破 θ_helpful − 遲滯帶(0.05)→ 退回 candidate(避免邊界抖動)
- 投票不足的卡片維持 candidate,對查詢者顯示但標註「脈絡待仲裁」

## 冷啟動特例

初期貢獻者不足以估計立場向量時:

1. Phase A(< 100 名活躍仲裁者):卡片以「查詢可見＋待仲裁標註」運作,不做顯示裁決;累積投票矩陣
2. Phase B:矩陣密度達標後啟動完整橋接計分;Phase A 期間投票全數保留參與訓練
3. 光譜多元度指標:立場向量分布的雙峰覆蓋度;儀表板公開,未達標時明示「本卡仲裁光譜尚未平衡」

## 抗操弄性質

- Sybil:行為一致的帳號群在分解中塌縮為同一立場向量,灌票增益次線性
- 突發灌票偵測:單卡投票速率異常(z-score)→ 該時窗投票降權並標記審計
- 貢獻者資格:投票需累積查詢行為紀錄(防純註冊機器人);無需實名
- 所有降權/標記規則開源,參數變更走公開 PR

## 重算節奏

- 批次全量重算:每小時(初期資料量下單機分鐘級)
- 卡片顯示狀態變更寫入審計 log(公開):時間、前後狀態、當次 i_c、投票數

## 對外輸出

- 每卡公開:i_c、有效投票數、光譜多元度指標(不公開任何個別投票)
- 研究者開放資料:匿名化投票矩陣(k-匿名處理)季度發布
