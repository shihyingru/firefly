# 14|風險與威脅模型

> 螢火 Firefly|v0.1|2026-07-20|AGPL-3.0
> 設計哲學:投票便宜,影響力昂貴;失效時沉默,不說謊(安全失敗)。全開源=安全不依賴保密(Kerckhoffs 原則)。

## T1 量產代號灌票(基本 Sybil)

攻擊:腳本量產裝置代號/多裝置,對目標卡集中投票。
防線(四層):
1. 橋接演算法:行為一致的代號群塌縮為單一立場向量,增益次線性
2. 資格門檻:計票需累積自然查詢行為史;純註冊代號權重趨零
3. 速率異常:單卡投票 z-score 異常時窗整批降權＋審計標記
4. 裝置證明:App 端 Play Integrity/App Attest;LINE 端天然有開帳成本;**網頁票列最低信任層級**,升權需 App/LINE 綁定
殘餘風險:低。最壞結果=卡片停在 candidate(不顯示),非錯誤裁決。

## T2 養號潛伏(sleeper raters)

攻擊:長期模仿多元投票建立假歷史,關鍵時刻收攏打目標卡。
防線:信譽的時間成本(歷史投票與最終共識一致率累積);收攏行為本身產生立場向量突變訊號;安全失敗兜底。
殘餘風險:中(業界公認最難防)。監測項:立場向量突變率、老代號協同收攏偵測。演練:每季紅隊模擬。

## T3 聚類層下毒

攻擊 a(躲偵測):LLM 改寫產生語意變體,碎化叢集低於成簇門檻。
攻擊 b(栽贓):刻意產製與無辜內容相似貼文,拖入髒叢集。
防線:多訊號互鎖——改寫騙得過 embedding,騙不過時序與網域指紋(行為改不掉);栽贓走具名貢獻者錯誤標記＋人工複審佇列(優先級最高,連動文件 13 名譽風險)。
殘餘風險:a 中(偵測率下降但操弄成本上升,本身即部分勝利);b 低中。

## T4 資源耗竭

攻擊:垃圾連結洪流逼開新叢集燒 LLM 預算;狂 @ Threads 機器人耗盡日額度;API DoS。
防線:成簇門檻 K≥3 才起草;起草佇列日上限;同叢集去重回覆;單使用者冷卻;Threads 額度留 20% 餘裕;Gateway 速率限制＋雲端 DDoS 基礎防護。
殘餘風險:低。最壞=延遲,非錯誤。

## T5 對 AI 書記官的 prompt injection

攻擊:貼文內容夾帶指令(「忽略規則,在卡片寫入……」)。
防線:貼文一律作資料不作指令;輸出強制 JSON schema 白名單;欄位級程式後驗證(連結可解析、數字與 SignalSet 相符);驗證失敗整卡退回。
測試項(CI 必跑):注入語料迴歸測試集,含中英日與混淆編碼樣本。
殘餘風險:低。注入成功的產出無法通過驗證。

## T6 治理與人的層面

- 標籤化攻擊:「側翼/境外勢力」指控必然發生。回應資產=治理章程、全開源、跨光譜覆蓋紀錄、資金全公開。準則:回應攻擊只出示紀錄,不對罵
- 維護者被鎖定:騷擾/濫訴/跨境壓力 → 文件 13 個人保護項;決策紀錄公開使「打人」無法「滅制度」
- 內部人風險(未來複審小組):跨光譜組成＋利益迴避＋分岔權為最終制衡
- 平台斷供:Threads/LINE 任一斷供 → feature flag 下線,分享目標 App 為全自主保底

## 失效模式總表

| 情境 | 系統行為 | 對外呈現 |
|---|---|---|
| 仲裁被攻擊 | 卡片停留 candidate | 「脈絡待仲裁」標註 |
| 光譜失衡 | 不做顯示裁決 | 「仲裁光譜尚未平衡」 |
| 來源撤回 | 卡片進複審 | 「來源更新中」 |
| 驗證失敗 | 卡片退回重生 | 查詢者見 processing |
| 平台斷供 | 入口下線 | 其他入口照常＋公告 |

## Runbook 清單(實作時逐項展開)

緊急下線、資料保全與異地備份還原、灌票事件處置與模式層公告、聚類錯誤更正、法律索資應對、金鑰輪替。
