# 02|使用者旅程與 UX 流程

> 螢火 Firefly|v0.1|2026-07-20|AGPL-3.0

## 使用者角色

| 角色 | 描述 | 核心動線 |
|---|---|---|
| 查詢者 | 滑到可疑貼文,想快速確認脈絡 | 丟連結 → 看脈絡卡 |
| 仲裁者 | 願意每天花三分鐘投票的貢獻者 | 看卡 → 一鍵投票 |
| 旁觀者 | 在 Threads 上看到機器人公開回覆的路人 | 看到卡 → 好奇 → 轉化為查詢者 |

設計原則:每個角色的下一步永遠只有一個動作;查詢者不需註冊；仲裁者以匿名裝置代號參與,可選擇性升級為具名貢獻者。

## 入口一:LINE Bot(第一波)

1. 使用者加入官方帳號好友(掃 QR 或搜尋 ID)
2. 貼上貼文連結或轉傳訊息
3. 機器人回覆脈絡卡(Flex Message):原始出處、最早出現時間、同文帳號數、快照連結
4. 卡片底部兩顆按鈕:「有幫助」「沒幫助」(postback,不離開對話)
5. 投票後回覆感謝語＋「明日佇列」選項(引導成為仲裁者)

無法生成卡片時(叢集未成立、非公開連結):回覆「目前查無協同訊號」＋通用識讀提示,絕不留白。

## 入口二:Threads 回覆機器人(第一波,並行技術驗證)

1. 使用者在任意貼文下回覆「@firefly_tw」(或含觸發詞)
2. 伺服器經 webhook 或輪詢取得提及,抓取母貼文
3. 官方帳號公開回覆脈絡卡摘要＋完整卡片連結
4. 投票在卡片連結頁完成(Threads 回覆內無互動元件)

額度守則:優先回應未回覆過的叢集;同叢集重複查詢回覆既有卡片連結,不重新生成。

## 入口三:手機分享目標(第二波)

- Android:系統分享面板 → 螢火 → Bottom Sheet 顯示卡片＋投票
- iOS:Share Extension → 同版面
- 查詢歷史保留在本機;可選擇開啟「仲裁佇列」通知

## 入口四:仲裁佇列(第二波後段)

- 每日推播 5 張待仲裁卡;左滑「沒幫助」右滑「有幫助」,上滑跳過
- 三分鐘完成;連續參與顯示貢獻天數(不做排行榜,避免衝量文化)
- 佇列組成由後端按「貢獻者光譜平衡」需求分配(見文件 05)

## 轉化漏斗

旁觀者 → 查詢者:Threads 公開回覆即獲客
查詢者 → 仲裁者:每次查詢後的單題輕邀請(「這張卡對你有幫助嗎?」本身即首次投票)
仲裁者 → 具名貢獻者:累積 N 次有效投票後邀請(解鎖提交補充出處的權限)

## 文案語氣準則

- 提問不斷言:「你有注意到這 32 個帳號在同一小時發文嗎?」而非「此為可疑內容」
- 不使用「假訊息」「闢謠」等裁決性詞彙;一律用「脈絡」「訊號」「證據」
- 查無訊號時明說查無,不暗示安全也不暗示危險
