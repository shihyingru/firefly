# 07|客戶端技術規格

> 螢火 Firefly|v0.1|2026-07-20|AGPL-3.0

## 7.1 LINE Bot(第一波)

- LINE Messaging API;webhook 伺服端整合於主後端(FastAPI route)
- 訊息處理:文字含 URL → 抽取正規化 → 呼叫 /lookup;轉傳訊息同法
- 卡片呈現:Flex Message 兩段式——摘要 bubble(出處/時間/帳號數)＋按鈕列(有幫助/沒幫助 postback、「看完整卡片」URI)
- 投票:postback event 帶 card_id,伺服端以 LINE userId 之單向雜湊為貢獻者代號(不存原始 userId 對照表);雜湊為 HMAC-SHA256,密鑰存環境變數,輪替走 runbook
- 回覆一律用 reply token(免費);不主動 push(成本與打擾雙零)
- /lookup 回 202(起草中)時:以 reply token 回覆「處理中」訊息,附「再查一次」按鈕(postback 帶原網址)。不 push、不等待
- 「今日佇列」:富選單 postback `queue:today`,以 reply 回 5 卡(零儲存)
- 引導期推播(D-014):加好友第 0 天以 reply 回佇列並邀請;同意者連續 N 天(初始 3)每日 push 5 卡,最後一次附自取說明;此為唯一 push 場景,受每日人數上限與 feature flag 管制

## 7.2 Threads 回覆機器人(第一波,技術驗證項)

- 官方帳號:@firefly_tw(待註冊);簡介明寫「自動回覆機器人|開源|發文紀錄公開」
- 觸發:優先 webhook(mention 事件,**上線前驗證可用性**);備援輪詢 keyword/mention 查詢,間隔 5 分鐘
- 回覆組裝:摘要文字(<500 字)＋卡片頁連結;同叢集重複觸發回既有連結
- 額度治理:每日回覆上限計數器(留 20% 餘裕);超量時僅回連結不生成新卡
- 風險開關:feature flag 可全域停用(Meta 政策變動時一鍵下線,不影響其他入口)
- App Review 材料:使用情境說明、隱私權政策連結、示範影片——列入上線 checklist

## 7.3 手機分享目標(第二波)

### Android
- Kotlin + Compose;`ACTION_SEND`(text/plain)intent-filter
- 收到分享 → 解析 URL → Bottom Sheet 顯示卡片(Compose)＋投票
- 貢獻者代號:裝置生成 UUID,存 EncryptedSharedPreferences
- 離線:顯示上次快取卡;查詢歷史僅存本機(Room)
- 仲裁佇列通知:WorkManager 每日一次;可於設定關閉

### iOS
- Swift;Share Extension(NSExtensionActivationSupportsWebURLWithMaxCount=1)
- Extension 內輕量卡片視圖;完整功能導向主 App(SwiftUI)
- 與 Android 共用 API 客戶端規格(OpenAPI 生成)

## 7.4 仲裁佇列(第二波後段)

- 形態:上述手機 App 內的分頁(非獨立 App)
- 手勢:右滑有幫助/左滑沒幫助/上滑跳過;每日 5 張,完成顯示貢獻天數
- 無排行榜、無徽章商店——避免衝量誘因扭曲仲裁品質

## 7.5 瀏覽器外掛(後期,規格佔位)

- WebExtension(Chrome/Firefox);Threads 網頁版 DOM 注入卡片指示器
- 依賴選擇器維護成本高,列後期;規格於啟動時另立文件

## 共通

- API 客戶端由 OpenAPI schema 自動生成(Kotlin/Swift/TypeScript)
- 所有客戶端不採集裝置識別以外的任何個資;無第三方分析 SDK
- UI 文案雙語資源檔;語氣遵循文件 02 準則
